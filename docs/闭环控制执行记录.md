## 当前不能直接实跑的原因

真实运行需要两个现场资产，目前机器人上还没有：

1. 四类方块 YOLO OpenVINO 模型  
   机器人现有模型只有 `best_traffic`、`garbage_classification`、`yolo11n/yolo11s` 等，没有 `competition_blocks.xml/bin`。真实运行前需要把四类模型放到：

```text
/home/ubuntu/ros2_ws/src/yolov11_detect/models/competition_blocks.xml
/home/ubuntu/ros2_ws/src/yolov11_detect/models/competition_blocks.bin
```

模型类别顺序必须是：

```text
redstone, glass, glowstone, grass
```

2. 比赛场地导航点  
   当前 `/home/ubuntu/ros2_ws/src/competition_pick_place/config/competition_waypoints.yaml` 仍是占位零坐标。真实运行前必须在 RViz/Nav2 中标定并写入：

```yaml
material_standoff_pose:
  x: ...
  y: ...
  yaw: ...
place_standoff_pose:
  x: ...
  y: ...
  yaw: ...
return_pose:
  x: ...
  y: ...
  yaw: ...
```

代码已加入保护：`dry_run:=false` 且 `use_nav:=true` 时，如果材料区或放置区仍是 `[0, 0]`，节点会直接进入 `FAILSAFE`，不会盲目出车。

## 最终实跑命令

模型和导航点准备好后，在 ROS2 容器中运行：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch competition_pick_place competition_run.launch.py \
  target_class:=grass \
  dry_run:=false \
  start_navigation:=true \
  start_yolo:=true \
  yolo_model:=competition_blocks \
  map_name:=competition_map
```

抽签目标变化时，只替换：

```bash
target_class:=redstone
target_class:=glass
target_class:=glowstone
target_class:=grass
```

如果目标放置区也有视觉标记，可额外设置：

```bash
place_class:=place_marker
```

否则放置阶段使用 Nav2 停车点加原厂 `navigation_place` 动作组完成。

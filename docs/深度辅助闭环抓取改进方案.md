# 深度辅助闭环抓取改进方案

## 背景

当前抓取成功率低的主要原因有两个：

1. 控制节奏不好调：控制太快会沿用滞后的 YOLO 结果，控制太慢又导致效率低、下探阶段微调不足。
2. 距离估计不稳定：现有方案用 YOLO 框面积估计远近，方块朝向变化会改变框面积，导致抓取触发距离漂移。

## 总体方案

采用“YOLO 负责类别和二维框，深度图负责真实距离”的组合策略：

- YOLO 继续输出 `red/green/blue` 检测框。
- 在检测框中心区域内读取深度图，取有效深度的中位数作为目标距离。
- 前后距离误差优先使用 `depth_m - target_depth_m`。
- 如果深度不可用、过期、编码不支持或有效点太少，自动回退到原来的 `target_area_ratio - area_ratio` 面积误差。
- 控制频率采用自适应节奏：最多每个新 YOLO 检测帧控制一次，控制周期根据检测帧到达间隔估计，避免既过快重复旧帧，也过慢浪费时间。

## 控制链路

```text
RGB image -> YOLO -> class + bbox + center
Depth image -> bbox center ROI median -> depth_m
center error = bbox cx - desired cx
distance error =
  if depth valid: depth_m - target_depth_m
  else: target_area_ratio - bbox_area_ratio
MPC/P controller -> short cmd_vel pulse -> zero stop
```

## 新增参数

### 深度距离

- `use_depth_distance`：是否启用深度距离，默认开启。
- `depth_topic`：深度图 topic，默认 `/ascamera/camera_publisher/depth0/image_raw`。
- `depth_stale_seconds`：深度帧最大允许年龄。
- `depth_unit_scale`：`16UC1` 深度单位转米比例，默认 `0.001`。
- `depth_roi_scale`：在 YOLO 框中心取多大比例的 ROI 采样。
- `depth_sample_grid`：ROI 内采样网格数量。
- `depth_min_valid_samples`：最少有效深度点数。
- `depth_min_m` / `depth_max_m`：合法深度范围。
- `pick_target_depth_m`：抓取前目标距离。
- `pick_depth_tolerance_m`：抓取前距离容差。
- `pick_preclose_target_depth_m`：下探/预抓取阶段目标距离；小于等于 0 时沿用 `pick_target_depth_m`。

### 自适应频率

- `adaptive_servo_timing`：是否根据检测帧率自适应控制周期，默认开启。
- `visual_servo_min_period`：最快控制周期下限。
- `visual_servo_max_period`：最慢控制周期上限。
- `visual_servo_period_scale`：检测帧间隔到控制周期的倍率。

## 调试顺序

1. 启动视觉后先确认深度 topic：
   ```bash
   ros2 topic list | grep -E "depth|ascamera"
   ```
2. 如果默认 topic 不对，在 UI 中修改 `depth topic`。
3. 打开画面，确认 YOLO 框正常。
4. 启动抓取，观察日志：
   - 出现 `depth=...m` 表示正在用深度。
   - 出现 `distance_source=area` 表示深度不可用，已回退到面积。
5. 先调 `target depth(m)` 和 `depth tolerance(m)`，再调速度。

## 第一版实施范围

本轮先实现：

- 深度图订阅和 ROI 中位数距离估计。
- 深度距离优先、面积距离回退。
- 自适应控制周期。
- UI 暴露深度和自适应频率参数。
- 本地编译检查。

暂不实现：

- 完整手眼标定和三维机械臂逆解。
- 点云坐标系转换。
- 自动搜索深度 topic 并重启节点。

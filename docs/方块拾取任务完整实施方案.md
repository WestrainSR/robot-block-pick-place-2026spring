# 方块拾取任务完整实施方案

> 任务已变更：当前训练和抓取目标为红、绿、蓝三种方块。本文中关于红石、玻璃、萤石、草方块的内容是早期方案背景，后续执行请以 `docs/方块识别网络训练流程.md` 和本地采集 UI 为准。

## 1. 任务目标与评分拆解

本方案面向 `第4章-短项目综合竞赛-V1.2.pptx` 中的“单件磁吸方块识别抓取速度竞赛”。机器人需要从启停区域出发，自主运动到原料存放区，在四类磁吸方块中识别抽签指定类型，抓取目标方块，将其放置到目标存放区，然后返回启停区域。

已知物料类型：

- 红石方块
- 玻璃方块
- 萤石方块
- 草方块

主要得分点：

- 正确到达原料存放区：2 分
- 正确识别目标物料：5 分
- 成功抓起目标物料：5 分
- 正确到达目标存放区：3 分
- 放置准确度：按色环 15/10/6/3/1/0 分
- 成功返回启停区：5 分
- 速度分：最快组 15 分，其余按比例

工程目标不是做最复杂的全自主系统，而是在比赛准备时间内稳定完成任务。推荐采用“官方示例改造 + 固定导航点 + YOLO 识别 + 官方机械臂抓取服务”的路线，把难度控制在可调试范围内。

## 4. 优先参考的开源/官方方案

降低工程难度的核心原则：不要从零写底盘、机械臂、相机、导航和深度定位，优先复制并改造现有示例。

建议参考：

- Hiwonder LanderPi 官方 Wiki 的机械臂、颜色分拣、自动抓取、导航搬运示例：`https://wiki.hiwonder.com/projects/LanderPi/en/latest/`
- 官方 `navigation_transport` 示例：逻辑最接近比赛任务，包含导航到目标点、识别、抓取、搬运、放置。
- 官方 `automatic_pick` 示例：可复用目标三维定位、机械臂逆解、抓取动作序列。
- 官方 `color_sorting` 示例：可复用夹爪开合、抓取/放置动作组和视觉处理结构。
- ROS2 Nav2 Simple Commander / Waypoint Follower：可用于 Python 状态机里发送导航目标。
- Ultralytics YOLO 文档：用于四类磁吸方块自定义检测模型训练与部署。

本项目推荐直接在机器人已有 `~/ros2_ws/src` 内查找这些示例文件：

```bash
cd ~/ros2_ws/src
find . -iname '*transport*' -o -iname '*pick*' -o -iname '*sorting*' -o -iname '*yolo*'
grep -R "navigation_transport\\|automatic_pick\\|color_sorting\\|yolov" -n .
```

## 5. 总体技术路线

推荐实现一个比赛专用 ROS2 包或脚本，名称建议为 `competition_pick_place`。它不重写底层能力，只做任务编排。

### 5.1 任务状态机

状态机：

1. `INIT`
   检查目标类别、模型、导航点、硬件节点是否就绪。

2. `NAV_TO_MATERIAL`
   用 Nav2 导航到原料存放区前的安全停车点。

3. `SEARCH_TARGET`
   启动 YOLO 检测，筛选抽签指定类别，例如 `grass`。

4. `ALIGN_TARGET`
   根据目标框中心和深度定位，低速微调底盘，使目标位于机械臂可抓取区域。

5. `PICK`
   调用官方自动抓取/逆运动学/舵机控制服务完成抓取。

6. `NAV_TO_PLACE`
   导航到目标存放区前的安全停车点。

7. `PLACE`
   执行固定放置动作，把物料放到色环中心附近。若场地图固定，优先用标定好的机械臂放置坐标。

8. `NAV_HOME`
   导航返回启停区。

9. `DONE`
   停止底盘，关闭检测，输出用时和结果。

10. `FAILSAFE`
    超时、未识别、抓取失败、导航失败时停车并释放资源。

### 5.2 推荐代码结构

在机器人上新建：

```text
~/ros2_ws/src/competition_pick_place/
  package.xml
  setup.py
  resource/competition_pick_place
  competition_pick_place/
    __init__.py
    competition_node.py
    detection_adapter.py
    nav_adapter.py
    arm_adapter.py
    config_loader.py
  config/
    competition_waypoints.yaml
    classes.yaml
  launch/
    competition_run.launch.py
```

如果机器人已有示例包不方便新增包，也可以先在 `~/ros2_ws/src/example/example/competition_pick_place/` 下放一个单脚本版本，等跑通后再包化。

### 5.3 单条命令启动

比赛规则要求“单条命令或按钮”远程启动。最终目标命令：

```bash
ros2 launch competition_pick_place competition_run.launch.py target_class:=grass map_name:=competition_map
```

抽签后只需要替换 `target_class`：

```bash
target_class:=redstone
target_class:=glass
target_class:=glowstone
target_class:=grass
```

## 7. 视觉模型方案

比赛方块按表面图样区分，不只是纯颜色，所以优先使用 YOLO 目标检测，不建议只用 LAB 颜色阈值。

### 7.1 类别命名

统一类别名：

```yaml
redstone: 红石方块
glass: 玻璃方块
glowstone: 萤石方块
grass: 草方块
```

### 7.2 数据采集

最低建议：

- 每类 150 到 200 张
- 四类同时入镜的数据至少 100 张
- 不同距离、角度、光照、背景都采集
- 保留比赛场地附近背景
- 标注框贴紧方块外缘

如果第三章项目已经训练过草方块模型，可以先复用；但比赛抽签可能是四类之一，因此最终模型应支持四类。

### 7.3 训练与部署

优先在本地电脑训练，机器人上只部署推理模型。训练命令示例：

```bash
yolo detect train model=yolo11n.pt data=data.yaml epochs=100 imgsz=640 batch=32
```

部署文件建议：

```text
~/ros2_ws/src/yolov8_detect/weights/competition_blocks.pt
```

机器人推理验证：

```bash
ros2 launch yolov8_detect yolov8_detect.launch.py model:=competition_blocks.pt
```

若官方 launch 参数不同，以机器人本地示例为准。要求目标类别检测置信度稳定高于 `0.7`。

## 8. 导航与场地标定

### 8.1 建图

如果比赛场地允许提前建图，先使用官方快速建图或 launch 文件建图。流程：

1. 将机器人放在场地内。
2. 启动 SLAM。
3. 用手柄或键盘让机器人绕自身旋转一圈，再沿场地边界慢速走一圈。
4. 保存地图，命名为 `competition_map`。

保存后确认地图文件位置：

```bash
find ~ -iname '*competition*map*' -o -iname '*.yaml'
```

### 8.2 记录导航点

通过 RViz 的 `2D Pose Estimate` 和 `2D Goal Pose` 调试，记录以下点：

- `start_pose`：启停区中心，朝向赛道。
- `material_standoff_pose`：原料存放区前方停车点，机械臂能看到方块。
- `place_standoff_pose`：目标存放区前方停车点，机械臂能把方块放到色环中心。
- `return_pose`：启停区返回停车点，通常等于 `start_pose`。

建议保存到：

```yaml
start_pose:
  x: 0.0
  y: 0.0
  yaw: 0.0
material_standoff_pose:
  x: 1.2
  y: 0.0
  yaw: 0.0
place_standoff_pose:
  x: 2.0
  y: 0.8
  yaw: 1.57
return_pose:
  x: 0.0
  y: 0.0
  yaw: 3.14
```

实际数值必须现场标定，不要直接使用上面的占位值。

## 9. 抓取与放置方案

### 9.1 抓取

优先复用官方三维定位和自动抓取：

- YOLO 输出目标框中心 `(u, v)`。
- 深度相机给出深度 `Z`。
- 官方三维定位节点把像素点转换为相机/机械臂坐标。
- 机械臂逆运动学服务输出舵机脉冲。
- 舵机控制节点执行抓取动作。

抓取动作序列沿用第二章课件建议：

1. 初始张开夹爪，脉冲约 `150`。
2. 移动到抓取点上方 `0.08 m`。
3. 下降到目标点。
4. 闭合夹爪，脉冲约 `350`。
5. 垂直抬升 `0.08 m`。

### 9.2 放置

放置优先用固定动作，不在比赛时做复杂视觉精放：

1. 导航到目标存放区前的标定停车点。
2. 机械臂移动到标定放置点上方。
3. 下降到色环中心附近。
4. 打开夹爪，脉冲约 `150`。
5. 抬升并收回。

如果放置误差大，再做一次场地标定：

- 调整 `place_standoff_pose`。
- 调整机械臂 `place_xyz_pitch`。
- 保证机器人每次停车朝向一致。

## 10. 调试顺序

按照从低风险到高集成的顺序调试。

### 10.1 连接与资源占用

```bash
~/.stop_ros.sh
ros2 node list
```

确认默认 APP 服务已关闭，硬件未被占用。

### 10.2 底盘运动

运行官方键盘或手柄控制，确认：

- 前进、后退、横移、旋转正常
- 机器人坐标方向与预期一致
- 电量充足，轮胎不打滑

### 10.3 相机与检测

检查相机话题：

```bash
ros2 topic list | grep -i image
ros2 topic list | grep -i depth
```

启动 YOLO 检测后确认：

- 四类方块都能识别
- 抽签目标类别名与参数一致
- 多目标时选择置信度最高且位置合理的目标

### 10.4 机械臂

先空载测试：

- 夹爪开合
- 回到初始姿态
- 到达抓取上方点
- 到达放置上方点

再放一个方块测试完整 pick/place。

### 10.5 导航

单独测试：

```bash
ros2 launch navigation2 navigation.launch.py map:=competition_map
```

实际 launch 名称以本机为准。逐点测试：

- 启停区到原料区
- 原料区到目标区
- 目标区回启停区

### 10.6 集成

先不开机械臂实抓，用 dry-run：

```bash
ros2 launch competition_pick_place competition_run.launch.py target_class:=grass dry_run:=true
```

再启用真实抓取：

```bash
ros2 launch competition_pick_place competition_run.launch.py target_class:=grass dry_run:=false
```

## 11. 失败处理策略

必须写入代码，避免比赛时卡死。

- 导航超时：停车，重试一次；仍失败则进入 `FAILSAFE`。
- 目标识别超时：原地小角度扫描 2 到 3 次；仍失败则停车。
- 多个同类目标：选择置信度最高、深度有效、离画面中心最近的目标。
- 深度无效：跳过该检测框，等待下一帧。
- 抓取失败：允许重抓一次；重抓前重新检测目标位置。
- 20 秒无移动风险：状态机每个阶段都要有动作或主动退出。
- 总时间限制：全流程设置 270 秒软超时，留 30 秒余量。

## 12. 最小可行版本

如果时间很紧，按以下 MVP 做：

1. 使用固定三点导航：原料区、目标区、启停区。
2. 只对抽签目标类别运行 YOLO 检测。
3. 到原料区后不做复杂搜索，只做小角度扫描和中心对齐。
4. 直接调用官方自动抓取例程。
5. 放置用固定机械臂坐标。
6. 返回启停区。

这个版本可争取得到到达、识别、抓取、到目标区、部分放置和返回分，工程复杂度最低。

## 13. 比赛前检查清单

- 电池充满，充电器断开。
- WiFi 已连接到 `HW-9E5ACFD8`。
- SSH/VNC/WinSCP 都能连上。

- `competition_waypoints.yaml` 是当天场地标定版本。

- 日志目录可写，赛后能导出代码包和视频/报告材料。

## 14. 推荐落地时间安排

第 1 阶段，30 到 60 分钟：

- 完成连接、关闭自启服务、确认工作空间和官方示例。

第 2 阶段，1 到 2 小时：

- 跑通官方 `automatic_pick` 或 `navigation_transport`。

第 3 阶段，2 到 4 小时：

- 训练/部署四类 YOLO 模型，确认检测稳定。

第 4 阶段，1 到 2 小时：

- 建图、记录导航点，单独测试三段导航。

第 5 阶段，2 到 4 小时：

- 编写比赛状态机并集成。

第 6 阶段，剩余时间：

- 只做参数调优和稳定性测试，不做大结构重构。
